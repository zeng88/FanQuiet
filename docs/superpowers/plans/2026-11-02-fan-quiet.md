# FanQuiet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a small native Mac app that highlights high-CPU processes and safely lets the user request termination of an eligible process.

**Architecture:** Plain Swift source separates process collection, parsing, policy, and termination from an AppKit executable. Direct `swiftc` scripts compile the self-test runner and package the executable and plist into `dist/FanQuiet.app`.

**Tech Stack:** Swift 5.1, Foundation, AppKit, direct `swiftc` builds, a dependency-free Swift self-test runner, macOS SDK from Command Line Tools.

**Spec:** `docs/superpowers/specs/2026-11-02-fan-quiet-design.md`

## Global Constraints

- Target device: Intel x86_64, macOS 12; build with Swift 5.1.3 and SDK 10.15.1 available on this host.
- Use AppKit and Foundation only; no third-party packages and no full-Xcode-only build step.
- Refresh the process snapshot every 3 seconds and show up to 15 processes sorted by CPU.
- Never terminate PID 0/1, root, another UID, protected system paths, or listed critical process names.
- Revalidate PID, UID, executable path, and start time before signaling; send `SIGTERM` only.
- No automatic termination, `sudo`, `SIGKILL`, fan control, launch agent, or login startup.
- Keep the user's existing TDD skill opt-out unrelated; this plan applies TDD to the FanQuiet implementation as requested.

## Review Focus

- **Malformed rows or executable paths containing spaces:** parser must ignore malformed rows and retain a valid full path; covered by `ProcessSnapshotParserTests` in Task 1.
- **CPU values above 100% or decimal values:** preserve and sort numeric values without clamping; covered by parser/sort tests in Task 1.
- **Empty process output or `ps` launch failure:** represent empty and failure distinctly so the UI cannot reuse stale kill actions; covered by provider and view-state tests in Tasks 1 and 3.
- **A process moves into a protected category:** system path, protected executable name, root UID, PID 0/1, or different UID must be denied with a reason; covered by `TerminationPolicyTests` in Task 2.
- **PID reuse or process identity changes while the confirmation dialog is open:** reject the request and send no signal; covered by `ProcessTerminatorTests` in Task 2.
