# FanQuiet 设计说明

## 意图

为 2015 款 Intel MacBook Pro（i7 / 16 GB / macOS 12）提供一个启动迅速、占用低的本地小工具。用户打开应用后能立即看到 CPU 占用最高的进程，并在确认后结束一个允许操作的进程，帮助定位持续高负载来源。

## 目标

- 启动后显示 CPU 排名前列的进程，突出显示当前最高项。
- 显示进程名、PID、CPU、内存、运行时长和保护状态。
- 允许用户选择可操作进程；结束前显示进程身份和影响说明，并要求确认。
- 只向当前用户的普通进程发送 `SIGTERM`；不请求管理员权限，不自动结束进程，不发送 `SIGKILL`。
- 对系统关键进程禁用结束操作，并说明保护原因。
- 进程列表定时刷新，避免持续高频采样增加老机器负担。

## 非目标与禁止行为

- 不控制风扇转速、电源管理、温控或系统完整性保护。
- 不修改系统设置、不安装后台服务、不在登录时自启动。
- 不提权，不结束 root 或其他用户的进程，不结束受保护的系统进程。
- 不自动清理、自动结束进程或把结束失败升级为强制终止。

## 约束

- 目标设备为 Intel x86_64、macOS 12；实现需兼容该系统。
- 当前构建环境为 macOS 12.7.6、Swift 5.1.3、Command Line Tools SDK 10.15.1，没有完整 Xcode，因此不依赖 Xcode 项目或新版 SwiftUI API。
- 使用 AppKit 和 Foundation；不引入第三方依赖。
- 应用以普通用户权限运行，最终产物为本地未签名 `.app`。

## 考虑过的方案

1. **原生 SwiftUI/AppKit**：原生体验好、额外依赖少。当前环境缺少完整 Xcode，SwiftUI 工程构建验证不稳，因此选用此方案中的 AppKit 部分。
2. **Python 图形界面**：快速搭建，但目标机器上的 Python 版本和打包运行时需要额外处理，启动与分发更复杂。
3. **Shell 工具**：最轻，但进程信息呈现、选择和确认保护较弱，不符合直观操作要求。

**选定方案：** AppKit + Foundation。直接用本机 Swift 编译器构建，界面保持简单，核心进程解析和安全规则可用独立测试覆盖。

## 界面与交互

- 主窗口显示当前 CPU 最高进程卡片和按 CPU 排序的前 15 个进程。
- 每行显示进程名、PID、CPU 占用、内存占用、运行时长及“可结束 / 受保护”状态。
- 窗口打开后立即采集，之后每 3 秒刷新一次。
- 可结束进程提供“结束进程”操作。点击后弹出确认框，显示名称、PID 和 SIGTERM 说明；取消不产生副作用。
- 受保护进程保留在列表中用于诊断，但不提供可点击的结束操作；界面显示保护原因。
- 采集失败时显示错误和重试入口，不显示可能过时的结束操作。

## 进程保护规则

- PID 0 和 PID 1 永远不可结束。
- 仅允许与应用相同有效 UID 的进程；root 和其他用户进程不可结束。
- 可执行文件位于 `/System`、`/usr`、`/bin`、`/sbin` 或 `/private` 等系统位置时不可结束。
- 对 WindowServer、loginwindow、launchd、kernel_task、Finder、Dock、SystemUIServer、coreaudiod、powerd 等关键进程名额外保护。
- 确认框出现后，发送信号前重新采集并核对 PID、UID、可执行文件和启动时间；身份已变化则拒绝操作，防止 PID 重用造成误结束。
- 满足全部允许条件后只发送 `SIGTERM`；权限不足或进程已退出时显示明确结果。

## 技术结构

- `ProcessSnapshotProvider`：调用系统 `ps` 获取一次快照，解析进程信息并按 CPU 排序。
- `ProcessSnapshot`：保存展示所需字段和用于二次核对的身份字段。
- `TerminationPolicy`：纯逻辑判断能否结束并返回保护原因。
- `ProcessTerminator`：二次核对身份后调用 `kill(pid, SIGTERM)`。
- `MainWindowController`：构建 AppKit 窗口、展示快照、刷新状态和确认流程。
- 系统 `swiftc` 直接构建核心、自测程序和 AppKit 应用；`build.sh` 将应用封装为 `dist/FanQuiet.app`，不依赖 SwiftPM 或 XCTest。

## 自测范围

- 用固定 `ps` 输出样本验证进程解析、空字段/异常行处理、CPU 排序和展示截断。
- 验证 PID 0/1、root、系统路径、关键进程名、其他 UID 均不能结束；普通当前用户进程可通过策略判断。
- 验证进程身份变化时拒绝发信号；测试中不向真实进程发送信号。
- 执行 `./self-test.sh` 和本地 `.app` 构建，检查生成的应用结构及最低系统版本声明；不要求安装完整 Xcode 或 SwiftPM 测试工具。

## 留给实现阶段的决定

- 根据 macOS 12 SDK 能编译的 API 选择窗口布局细节；避免视觉效果依赖新系统能力。
- 采集输出解析采用固定字段顺序和明确的错误状态；确认前复用同一采集器做身份复核。
- 不在应用中常驻后台；窗口关闭后停止刷新。
